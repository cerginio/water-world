# Стенд станів `quest-demo-qa` і контракт сцени

Фази QDa (контракт) і QDb (стенд і оболонка) спеки [STORY-QUEST-SPEC.md](../../STORY-QUEST-SPEC.md) (§4.4, §8). Рішення
власника 2026-11-25.

## Навіщо

QA-сценарії Q1–Q5b щоразу починаються з довгого ручного шляху: дійти до
мініатюри, гідратувати, стати на пліт, підняти кайт, вийти в море, злетіти,
втопити, пірнути. Стенд доводить сцену до такого стану однією карткою, без
вводу, після чого з нею можна експериментувати руками. Продукт Q7 побудовано
на тій самій оболонці, тож він має майже такий самий вигляд.

## Сторінка

`products/quest-demo-qa/index.html` — третій вхід збірки (`build.rollupOptions.input`,
`verify-dist`). Компонування — як `story-demo` у Tilecraft: сцена в `<iframe>` на
весь екран, бічна панель `product-panel` (ковзна або накладна), на телефоні
відкривається кнопкою ☰.

Зони панелі задає `ui-map` стенду. Спільний рендер зон лежить у `products/shared/`.

| зона | що в ній | `story-quest` (Q7) |
|---|---|---|
| Історія | каталог R2 за папками (`test-2025/`, `public-test/`), запасні фікстури dev | так |
| Стани | картки станів, згруповані: острів · мініатюри · пліт і кайт · політ · долі · вода | ні |
| Погода | настрій і пресети через контракт (`mood.set`) | так |
| Квести | місце під Q6 (у QD порожнє) | так |
| Тех | fps, технічні панелі сцени, `state.read` у вигляді тексту | ні |

Дія будь-якої зони застосовується до **одного** спільного iframe.

## Картка стану

Картки — це дані `products/quest-demo-qa/states.json`, а не код:

```json
{
  "id": "raft-kite-open-sea",
  "group": "raft",
  "title": { "uk": "Пліт під кайтом у відкритому морі", "en": "Raft under kite, open sea" },
  "covers": ["QA-Q4-3", "QA-Q4-4", "QA-Q5a-1"],
  "story": "test-2025/my-day-3-moments",
  "flags": ["walk", "minis"],
  "weather": { "preset": "clear" },
  "steps": [
    { "cmd": "minis.hydrate", "at": "frame:0", "where": "shallow" },
    { "cmd": "raft.board", "frame": 0 },
    { "cmd": "kite.raise" },
    { "cmd": "raft.moveTo", "at": "open-sea" }
  ],
  "expect": { "mode": "raft", "kite": "up", "openSea": true }
}
```

- **Застосування — телепорт командами** (§4.4). Шлях у реальному часі не
  програється. Кожен крок чекає своєї події, ціль — до 10 с на картку після
  завантаження історії.
- **Чистий старт.** Картка перезавантажує iframe з адресою, складеною з `story`,
  `flags` і `weather`, і лише потім виконує кроки. Стан не залежить від
  попередньої картки.
- **Прогрес видно.** Картка показує кроки з позначками (чекає · виконано ·
  відмова з причиною). Якщо стан не зібрався, видно, на якому кроці.
- **`covers`** — довідка: які сценарії QA.md ця картка скорочує. QA.md на
  картки не посилається (рішення власника).
- **Адреса стенду** `quest-demo-qa/?story=…&card=<id>` відкриває його одразу в
  стані. Це зручно, щоб поділитися станом, але це не формат `qa:open`.

Перший набір карток охоплює стани Q2a–Q5b. Точний перелік фаза складає з
індексу QA.md, по одній картці на стан, з якого починається група сценаріїв:
на пляжі «очима» · «поза тілом» · мініатюра в руках · мініатюра у воді
(гідратована) · на плоті без кайта · пліт під кайтом біля берега · пліт у
відкритому морі · політ над глибиною · політ до острова · кадр втоплено ·
кадр відпущено · кадр розпався · у воді на поверхні · під водою біля
втопленого кадру.

## Контракт сцени (`src/embed/`)

- Вмикається параметром `&embed`: сцена ховає технічні панелі й слухає
  `postMessage` лише від `parent` того самого origin.
- Протокол — за зразком Tilecraft `lib/message-api.js`: hello/ready з повтором,
  RPC `call(cmd, args) → { ok, state } | { ok: false, reason }`, події.
- Команди — закритий перелік. Невідома команда дає відмову
  `unknown-command`, а не виняток. Реалізація викликає ті самі функції, що
  кнопки й клавіші сцени, без обхідних шляхів. Камера йде лише через
  `cameraRig` (OWNER-3).
- Якорі розв'язує сцена для поточної історії: `beach`, `frame:<n>`,
  `shallow`, `open-sea`, `deep`, `deep-over-sunk`, `island`.
- `window.app` лишається налагоджувальною поверхнею для проб. Продукт його не
  читає.

## Межі

- `products/**` не імпортує `src/**` і не звертається до
  `iframe.contentWindow.app`. Це новий рядок guard, його валить мутація
  `import '../../src/main.js'` у `products/`. Правило без винятків:
  `products/story-quest/` переходить на спільну оболонку в тій самій фазі
  (рішення власника 2026-11-25), із зонами Історія й Погода.
- Без нових залежностей. Tilecraft лише читається: `message-api.js` слугує
  зразком протоколу, а не імпортом у продукт.

## Перевірки фази

- **guard:** нове правило «products ↛ src» з мутацією; OWNER-3 не росте.
- **focused:** юніти `src/embed/`: закритий перелік, відмова невідомої
  команди, розв'язання якорів на фікстурі, тайм-аут кроку.
- **проба** `probe-story-states.mjs`: кожна картка з `states.json` на
  стенді досягає свого `expect` (через `state.read`); перезавантаження з
  `&card=` дає той самий стан.
- **телефон:** драфт Netlify (`--alias story-quest`), шлях
  `/products/quest-demo-qa/`. Картка вибирається дотиком, після неї — дотики
  в сцені.
