# Стенд станів `quest-demo-qa` і контракт сцени

Фази QDa (контракт) і QDb (стенд і оболонка) спеки [STORY-QUEST-SPEC.md](../../STORY-QUEST-SPEC.md) (§4.4, §8). Рішення
власника 2026-11-25.

## Навіщо

QA-сценарії Q1–Q5b щоразу починаються з довгого ручного шляху: дійти до
мініатюри, гідратувати, стати на пліт, підняти кайт, вийти в море, злетіти,
втопити, пірнути. Стенд доводить сцену до такого стану однією карткою, без
вводу, після чого з нею можна експериментувати руками. Продукт Q7 побудовано
на тій самій оболонці, тож він має майже такий самий вигляд.

## Сторінка

`products/quest-demo-qa/index.html` — третій вхід збірки (`build.rollupOptions.input`,
`verify-dist`). Компонування — як `story-demo` у Tilecraft: сцена в `<iframe>` на
весь екран, бічна панель `product-panel` (ковзна або накладна), на телефоні
відкривається кнопкою ☰.

Зони панелі задає `ui-map` стенду. Спільний рендер зон лежить у `products/shared/`.

| зона | що в ній | `story-quest` (Q7) |
|---|---|---|
| Історія | каталог R2 за папками (`test-2025/`, `public-test/`), запасні фікстури dev | так |
| Стани | картки станів, згруповані: острів · мініатюри · пліт і кайт · політ · долі · вода | ні |
| Погода | настрій і пресети через контракт (`mood.set`) | так |
| Квести | місце під Q6 (у QD порожнє) | так |
| Тех | fps, технічні панелі сцени, `state.read` у вигляді тексту | ні |

Дія будь-якої зони застосовується до **одного** спільного iframe.

## Картка стану

Картки — це дані `products/quest-demo-qa/states.json`, а не код:

```json
{
  "id": "raft-kite-open-sea",
  "group": "raft",
  "title": { "uk": "Пліт під кайтом у відкритому морі", "en": "Raft under kite, open sea" },
  "covers": ["QA-Q4-3", "QA-Q4-4", "QA-Q5a-1"],
  "story": "test-2025/my-day-3-moments",
  "flags": ["walk", "minis"],
  "weather": { "preset": "calm" },
  "steps": [
    { "cmd": "minis.hydrate", "args": { "frame": 0 } },
    { "cmd": "raft.board", "args": { "frame": 0 } },
    { "cmd": "kite.set", "args": { "up": true } },
    { "cmd": "raft.moveTo", "args": { "frame": 0, "at": "open-sea" } }
  ],
  "expect": { "walker.deck": 0, "kite": true, "openSea": true }
}
```

- **`weather`** — `{ "preset": <якір мапи настрою>, "t"?: <час доби> }`, застосовується
  першим кроком `mood.set` (сцена не читає погоду з адреси; QDb).
- **`expect`** — шляхи в `state.read` (`walker.swim.depth`, `frames.1.fate.kind`):
  `true`/`false` — істинне/хибне, `{ "min", "max" }` — межі числа, інше — рівність.
  Після кроків стенд читає `state.read`, доки очікування не збудеться (до 10 с).
- **Історія.** `story` картки — за замовчуванням; вибрана на стенді (зона «Історія»,
  `?story=`) її перекриває.
- **Застосування — телепорт командами** (§4.4). Шлях у реальному часі не
  програється. Кожен крок чекає своєї події, ціль — до 10 с на картку після
  завантаження історії.
- **Чистий старт.** Картка перезавантажує iframe з адресою, складеною з `story`,
  `flags` і `weather`, і лише потім виконує кроки. Стан не залежить від
  попередньої картки.
- **Прогрес видно.** Картка показує кроки з позначками (чекає · виконано ·
  відмова з причиною). Якщо стан не зібрався, видно, на якому кроці.
- **`covers`** — довідка: які сценарії QA.md ця картка скорочує. QA.md на
  картки не посилається (рішення власника).
- **Адреса стенду** `quest-demo-qa/?story=…&card=<id>` відкриває його одразу в
  стані. Це зручно, щоб поділитися станом, але це не формат `qa:open`.

Перший набір карток охоплює стани Q2a–Q5b. Точний перелік фаза складає з
індексу QA.md, по одній картці на стан, з якого починається група сценаріїв:
на пляжі «очима» · «поза тілом» · мініатюра в руках · мініатюра у воді
(гідратована) · на плоті без кайта · пліт під кайтом біля берега · пліт у
відкритому морі · політ над глибиною · політ до острова · кадр втоплено ·
кадр відпущено · кадр розпався · у воді на поверхні · під водою біля
втопленого кадру.

## Контракт сцени (`src/embed/`)

- Вмикається параметром `&embed`: сцена ховає технічні панелі й слухає
  `postMessage` лише від безпосереднього `parent` з точним дозволеним origin.
  Без `embed-origin` — поточний origin; EX-6a додає `https://explore.storytilecraft.space`,
  `http://127.0.0.1:8184` — лише в dev. Значення URL не розширює allowlist (SECURITY-1).
- Протокол — за зразком Tilecraft `lib/message-api.js`: hello/ready з повтором,
  RPC `call(cmd, args) → { ok, state } | { ok: false, reason }`, події.
- Команди — закритий перелік. Невідома команда дає відмову
  `unknown-command`, а не виняток. Реалізація викликає ті самі функції, що
  кнопки й клавіші сцени, без обхідних шляхів. Камера йде лише через
  `cameraRig` (OWNER-3).
- Якорі розв'язує сцена для поточної історії (`src/embed/anchors.js`):
  `beach` (місце старту персонажа), `shallow` (лінія броду навпроти поля, обличчям
  у море), `open-sea` (азимут поля, 1300 м від центру), `frame:<n>` і `over:<n>`
  (де кадр n зараз; мініатюра — там, де мініатюра), `beside:<n>` (6 м від обода
  палуби n уздовж її осі u). Кадр — індекс у порядку реєстру кадрів, не id.

Команди (QDa, `src/embed/commands.js`; кожна повертає `state.read`):

| команда | аргументи | що робить |
|---|---|---|
| `state.read` | — | режим, персонаж (`deck`, `flight`, `landing`, `board` — `sit`/`plane`/`air` з Q9, `swim`), кайт, `openSea`, `carried`, підказки кнопок, кадри (`mini`, `deck`, `fate`) |
| `walker.place` | `at`, `yaw` | ноги на ґрунті в якорі, «очі» |
| `walker.eyes` | `on` | у тіло / «поза тілом» |
| `walker.look` | `yaw`, `pitch`, `at` | погляд |
| `minis.take` | `frame` | мініатюра в руки |
| `minis.hydrate` | `frame` | узяти, покласти на `shallow`, дочекатися палуби на воді |
| `minis.put` | `settle` | мініатюру з рук — туди, де персонаж: на ґрунт, або (над морем, у воді, з дошки) розгорнути на воді; `settle` чекає палуби (Q10) |
| `minis.lift` | `frame` | кадр з води знову мініатюрою в руки (та, що в руках, — у рюкзак); не палуба під ногами й не кадр під долею (Q10) |
| `raft.board` | `frame`, `u`, `v`, `yaw` | на палубу кадру |
| `raft.moveTo` | `frame`, `at` | палуба (з персонажем, якщо це пліт) у якір |
| `kite.set` | `up` | кайт |
| `fly.takeOff` · `fly.to` · `fly.land` | `at` для `fly.to` | дошка: на воду з плоту чи з води (Q9), над якорем, посадка |
| `fate.give` · `fate.undo` · `fate.keep` | `frame`, `kind`, `settle` | доля; `settle` чекає кінця на годиннику ×10 |
| `swim.in` · `swim.dive` · `swim.rise` | `at`, `depth` | у воду (з якоря, з плоту, з дошки), глибина одразу |
| `mood.set` | `v`, `a`, `t` | погода |
| `catalog.list` | `local` | історії за папками (`{ stories, errors, fallback }`); `local` — і фікстури dev (стенд); сцени не чекає (QDb) |
| `catalog.read` | — | стан каталогу: `{ state, story, error }` (QDb) |
| `scene.tech` | `controls`, `fps` | технічні панелі сцени й частота кадрів (зона «Тех», QDb) |

Відмови: `unknown-command`, `bad-args`, `unknown-anchor`, `unknown-frame`,
`not-on-water`, `no-miniature`, `not-possible`, `story-failed`, `catalog-failed`, `timeout`.
Події: `scene.ready` / `scene.failed`, `minis.take|put|unfold|hydrate|pack|unpack|lift`,
`raft.board|leave|kite|sea|takeoff|land`, `fate.change`, `catalog.change` (одразу, без
сцени: `{ state, story, error }`).
- `window.app` лишається налагоджувальною поверхнею для проб. Продукт його не
  читає.

## Межі

### Зовнішній embed продукту (explore-ux EX-6a)

`/products/story-quest/?story=<folder/slug>&embed&embed-origin=https://explore.storytilecraft.space`
вбудовує **оболонку**, а не голу сцену. Корінь `/` лишається платформою; внутрішній iframe сцени —
та сама межа BOUNDARY-5. Один зовнішній iframe продукту, один вкладений iframe сцени, один WebGL-контекст.
У самостійній вкладці продукт працює звичайно, зовнішній канал неактивний.

Оболонка відповідає тим самим `ultra-water/scene` v1 (hello/ready, RPC), не імпортуючи `src/**`.
Перелік команд повертає ready: лише allowlist passthrough для станів/погоди, lifecycle та `quest.start`.
Немає API читання/запису приватних карток думок; їхні тексти не виходять у зовнішній хост.

- `activate` — ack після фактично намальованого кадру (у прихованому документі повертає `active:false`).
- `deactivate` — ack після скасування RAF і зупинки симуляції; час скидається перед resume.
- `dispose` — зупинка, від'єднання embed listeners, renderer dispose/context loss, видалення внутрішнього iframe;
  оболонка віддає останнє підтвердження й відключає зовнішній listener. Повторне використання — новий продукт.
- `quest.start { id: 'find' }` — відкрити задачу «Знайти частини», персонаж на пляжі; пошук робить користувач.
- `quest.start { id: 'note' }` — відкрити редактор із підказкою «Що я відчуваю зараз?».
- Успіх: `{ ok:true, value:{ id, status:'started' } }`; невідомий id — `unknown-quest`, журнал ще не готовий —
  `not-ready`, паралельний запуск квесту — `busy`. Старт **не** позначає задачу виконаною.

Клієнтський timeout включає очікування ready: після його спливу пізній handshake не запускає стару команду.
Перевірка: `scripts/probe-story-embed.mjs --product`; dev або production artifact / hosted draft;
`PLAYWRIGHT_CHANNEL=chrome` використовує встановлений браузер. Результати EX-6a — у канонічному
`D:/work/js-games/ua-dream/tilecraft/_docs/explore-ux/HANDOFF.md`. Власник додав R2 CORS для water;
production-проба оболонки `--product` PASS **17,2 с**, код і deploy не змінювали.

- `products/**` не імпортує `src/**` і не звертається до
  `iframe.contentWindow.app`. Це новий рядок guard, його валить мутація
  `import '../../src/main.js'` у `products/`. Правило без винятків:
  `products/story-quest/` переходить на спільну оболонку в тій самій фазі
  (рішення власника 2026-11-25), із зонами Історія й Погода.
- Без нових залежностей. Tilecraft лише читається: `message-api.js` слугує
  зразком протоколу, а не імпортом у продукт.

## Перевірки фази

- **guard:** нове правило «products ↛ src» з мутацією; OWNER-3 не росте.
- **focused:** юніти `src/embed/`: закритий перелік, відмова невідомої
  команди, розв'язання якорів на фікстурі, тайм-аут кроку.
- **проба** `probe-story-states.mjs`: кожна картка з `states.json` на
  стенді досягає свого `expect` (через `state.read`); перезавантаження з
  `&card=` дає той самий стан.
- **телефон:** драфт Netlify (`--alias story-quest`), шлях
  `/products/quest-demo-qa/`. Картка вибирається дотиком, після неї — дотики
  в сцені.
