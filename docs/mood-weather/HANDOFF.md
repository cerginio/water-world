## НЕЗАКРИТЕ — почни звідси

Порядок тем, визначений власником 2026-11-23: **scene-environment E0 → E1 →
M1a → M1b → scene-environment E2 → M2 → …** `main.js` у цей час не правлять
паралельно інші теми. Мапа залежностей:

| фаза | чекає на |
|---|---|
| M1a | scene-environment E1 (`src/environment/` існує) |
| M1b | M1a |
| M2 | scene-environment E2 (`setState`/`update` з τ і дроселем) |
| M3 | M1b |
| M3b | M2, M3 |
| M4 | EDGE W5 ([EDGE-OF-THE-ELEMENTS-SPEC.md](../../EDGE-OF-THE-ELEMENTS-SPEC.md), стан світу) |

scene-environment E3 (LDR) бере `MOOD_MAP_V1` з M1a.

Guard для всіх фаз: `npm run guard` зелений (OWNER-1…5, BOUNDARY-1…3,
BUDGET-1, TEX-1, TYPES-1); `npm test` зелений; `?tiles=none` і
`runBenchmark({ shot })` поводяться як до фази. Порядок перевірок —
guard → focused → probe ([TESTING.md](../../TESTING.md#рівні-прогону)).
Стан у QA до M4 ставиться через `app.mood.set()` (рішення власника
2026-11-23: URL `?mood=`/`?day=` — у M4, як у спеці).

1. **M1a — дані, прив'язки й один писар сонця, без UI** (спека §2.2, §3, §5).
   `src/environment/mood.js` (`MOOD_MAP_V1`, `sampleMood` білінійно,
   `SUN_PATH_V1`, `sunAt`); `src/environment-bindings/seaBinding.js` (sea →
   `OceanSim`, `surface.uniforms`, `spray`, `WATER_PRESETS`, туман); поле
   історії на сталому азимуті 205° замість `sunBearing()`; шоти й слайдери
   Controls пишуть сонце через стан оточення; дебаг-API
   `app.mood.set(v, a, t)` (миттєво, з перепіканням) і `app.mood.state()`.
   - guard: **OWNER-4 6 → 0** (baseline опускається в тому ж коміті);
     BOUNDARY-2 покриває `mood.js`.
   - focused: юніти `sampleMood` (9 якорів = таблиця §3.2, центр комірки —
     середнє, неперервність на межах) і `sunAt` (таблиця §2.2).
   - проба: `app.mood.set` для 9 якорів дає параметри §3.2; зміна `t` до й
     після завантаження тайлів не зсуває поле (§6 п.10); знімки `Tiles` під
     9 якорями × `t` 0.05 / 0.5 / 0.95 — білий ≥ 0.55, чорний ≤ 0.25 sRGB
     (§6 п.5). Провал підлоги — калібрування якорів з власником, не
     підкручування критерію.

2. **M1b — віджет** (спека §4.1, §4.2 без змісту, §4.3 без плину, §4.5).
   `src/environment/ui/moodPad.js`: кругла кнопка 56 px у слоті
   `--weather-slot` (зарезервувала scene-ui U3); розгорнутий — дуга сонця й
   вікно погоди 240 px (телефон — нижній лист, до 320 px), камінчик тягнеться,
   дотик переносить; небо перепікається на відпускання; ручна зміна в
   Controls → стан «власне» (камінчик і сонце напівпрозорі).
   - проба: перетяг у вікні й на дузі дає очікувані `(v, a, t)` у
     `app.mood.state()`; перше відкриття — `t = 0.1`, A9 (§6 п.2); у DOM
     віджета немає цифр і `input[type=range]` (§6 п.9); зміна слайдера
     Controls → `custom: true`, наступний дотик → `false`.
   - QA очима: телефон — лист не перекриває рейку.

3. **M2 — плавні переходи** (спека §4.4). τ 6 с (сонце, світло, небо) і 10 с
   (море) через стан оточення з E2; `updateSpectrum` щокадру під час
   переходу моря.
   - проба: A9 → A1 — параметри моря й неба змінюються монотонно, без
     стрибків між кадрами; 95 % за ~3τ.
   - очі власника: запис екрана A9 → A1 і назад, світанок → захід (§6 п.3);
     Nord 4 ≥ 30 FPS з `autoResolution` (§6 п.8).

4. **M3 — зміст віджета** (спека §4.1, §4.2). Ілюстрації дев'яти якорів
   (CSS-градієнти + SVG), чотири слова по краях, емоційні слова з
   перехрестям (на межі — обох станів), назва якоря на довгому натисканні,
   запрошення зі згортанням після першого жесту, мініатюра й кільце
   прогресу на кнопці; слова в локалях uk/en.
   - проба: у A9 — «спокій · умиротворення» (§6 п.7); запрошення видно при
     кожному відкритті (§6 п.12); мова — за `navigator.languages`.

5. **M3b — поведінка й безпека** (спека §4.3, §4.6). «Затихнути» (видима
   при `a > 0.3`, τ 8 с), плин дня 20 хв з автовимкненням на заході,
   `prefers-reduced-motion` (`a ≤ 0.3`, τ ×1.5), клавіатура (←/→ 0.05 дня,
   стрілки 0.25, `Enter`, `Esc`), три `role="slider"`, `aria-live`.
   - проба: «Затихнути» з A1 → A9 за 25 ± 5 с, `t` незмінний (§6 п.4);
     reduced motion + A1 → `waveScale ≤ 0.12`, `windSpeed ≤ 7` (§6 п.6);
     плин дня — вимкнений після першого відкриття, зі стиснутим годинником
     доходить до заходу й вимикається (§6 п.11).

6. **M4 — стан світу** (спека §4.7). `mood: { t, v, a, flow, map: 'mood@1' }`
   у частині `edge-of-the-elements`; URL `?mood=v,a&day=t`. Після EDGE W5.
   - проба: `?mood=1,-1&day=0.1` відкриває A9 вранці; стан з іншою версією
     матриці не відкривається як поточний.

### Відкриті питання

- **Спека §8:** назви якорів і слова (п.1) — потрібні до M3; тривалість плину
  дня 20 хв (п.2) — до M3b.
- **Застаріле посилання в спеці §2.2:** поле історії прив'язане до сонця не
  в main.js:286, а в `storyAnchor` ([main.js:261](../../src/main.js#L261)).
- **Підлога читабельності (§6 п.5) зі стартовими параметрами §3.2 не
  виміряна:** якщо M1a її не тримає, параметри якорів калібрує власник.
- **Заміри на Nord 4** (M2 §6 п.8) і записи екрана (§6 п.3) — лише власник.

## Головні виміряні факти

### Сонце й поле історії

- [писати сонце після scene-environment E1] параметри сонця — `env.params` (`createEnvironment`, [src/environment/index.js](../../src/environment/index.js)), у консолі `app.env`; OWNER-4 рахує й `env.params`, і `sky.params` → новий писар іде через оточення, `mood.js` лягає в `src/environment/` під BOUNDARY-2. (E1)
- [знімки під якорями] `?still` + `app.still({ shot: 'Tiles' })` дає кадр без часу, детермінований до Δ 0 (`probe-scene-env-identity`) → брати його для знімків §6 п.5, а не живий цикл. (E1)

- [зміна часу доби до завантаження тайлів] `storyAnchor` кешує кут із `sunBearing()` при першому виклику → без прив'язки до сталих 205° поле історії стане туди, куди було сонце в цю мить. (план)
- [`setSun` у шотах] шоти ставлять сонце відносно `sunBearing()` ([main.js:194–261](../../src/main.js#L194)) → один писар сонця в M1a має лишити шоти на тих самих позах камери. (план)
