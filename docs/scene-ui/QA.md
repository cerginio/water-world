## U3. Мобільний профіль, доступність, мова

**Прийнято власником через `handoff:next` 2026-11-23.** Драфт-деплой Netlify зроблено
перед прийманням. Guard зелений за 0.39 с (OWNER-3 0, власник `cameraRig.js`
— 9 записів; OWNER-4 6; TYPES-1 21). `npm test` 55/55, lint чистий. Проби (AMD Radeon
890M, Chromium ANGLE D3D11, `errors=[]`): нова `probe-scene-mobile` PASS 18 с;
регресія `probe-scene-rail` PASS 94 с, `probe-scene-frame` 145 с і `probe-scene-ui` — PASS.

Що змінилося: на телефоні (клас `mobile`) рейка тягнеться на всю ширину з відступами
16 px зліва й знизу, справа лишається порожнє місце 56 + 8 px під круглу кнопку
погоди (саму кнопку робить MOOD-WEATHER). Вузли однакові за шириною (`1fr`). У
`viewport` додано `viewport-fit=cover`: без нього `env(safe-area-inset-*)` завжди 0 і
рейка на телефоні з вирізом/жестовою смугою стояла б під нею. Телефон у альбомній
орієнтації (висота ≤ 500 px): `#perf` переходить угору ліворуч, бо над смужкою F2/F3
для нього немає місця. Рейка має `lang` своєї мови: зчитувач екрана читає «Острів»
українською навіть на англомовній сторінці.

Автоматично: `node scripts/probe-scene-mobile.mjs` на трьох в'юпортах — 412×915
(`uk-UA`), 360×780 і 915×412 (`en-US`). Рейка: лівий край 16 px, нижній — за 16 px від
низу, правий — за 16 + 56 + 8 px від правого краю; місце під погоду вільне (під ним
canvas). Зони дотику: вузли 79×64 / 66×64 / 205×64, кнопки смужки 95×44 і 67×44.
Рейка, смужка й `#perf` не перекриваються, усе в межах екрана. aria: `<nav>` з
`aria-label`, вузли — `<button type="button">` з `aria-label`, після дотику до «Берег»
`aria-current="location"` лише на ньому, без тайлів «Історія»/«Мить» мають
`aria-disabled` і пояснення в `aria-label`. Клавіатура: Tab доходить до «Island»,
видно кільце `solid 2px` блакитне, Enter летить на острів. Мова й `lang` — за
мовою браузера.

Очима — те, чого проба не бачить: `safe-area-inset-*` у Chromium не емулюється (там
0), тож відступ над жестовою смугою справжнього телефона видно лише на ньому; чи
кільце фокусу помітне на світлій воді; FPS на OnePlus Nord 4 (§4.7 п.8).

Телефон: стенд слухає лише `localhost`. Для QA-U3-1…4 підняти стенд з `--host`
(`npm run dev -- --host`) і відкрити `http://<IP ПК>:5199/` — дивись преамбулу.

## U1. Рейка станцій і переліт камери

**Прийнято власником через `handoff:next` 2026-11-23.** Драфт на Netlify
(`edge-of-elements`, 2026-11-23) власник дивився на телефоні; там знайдено квадрат
мілини навколо острова — дефект старший за U1, виправлення — фаза U4. Guard зелений за 0.23 с: OWNER-3 27 → 0 (камеру пише
лише `src/scene/cameraRig.js`, 7 записів), OWNER-4 6, TYPES-1 21. `npm test` 49/49
(31 новий), lint чистий. Проби (AMD Radeon 890M, Chromium ANGLE D3D11, `errors=[]`):
`probe-scene-rail` PASS 97 с; регресія `probe-frame-drag` 34 с (`FD2_SKIP_SOAK=1`),
`probe-scene-ui` 56 с, `probe-frame-lifecycle` 53 с, `probe-tiles` 59 с — PASS.

Автоматично: `node scripts/probe-scene-rail.mjs` записує позу камери **кожен кадр**
9 перельотів (з Lagoon, з-під води, з Aerial, з Tiles; острів ↔ берег ↔ історія):
0 кадрів під рельєфом, 0 кадрів посередині перельоту нижче води + 1 м, найбільший крок
за кадр ≤ 7.5 % шляху, `sky.params` і `ocean.params` незмінні, тривалість ≤ 5 с.
Також: натискання на canvas під час перельоту, захоплення кадру на 80 % перельоту,
неактивна «Історія» без тайлів, клавіші, reduced motion, перекриття рейки й смужки
F2/F3 на телефоні. Очима — те, чого проба не бачить: чи переліт **виглядає** плавним,
що видно з берега, вигляд рейки й намистинки.

- Тривалість перельоту рахується в часі кадрів (`dt` ≤ 0.1 с на кадр): на кадрах-ривках
  > 100 мс переліт на стіні триває довше 5 с (headless-стенд: 5.6–7.9 с; такі самі

  квадрат ~1800 м світлої гладкої «мілини» з прямою межею (карта берега читається як нулі).
  Зі станції «Острів» його видно найкраще. Виправлення — фаза U4.
