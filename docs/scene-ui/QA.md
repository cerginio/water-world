# QA: scene-ui

Локально з каталогу `D:/work/_tools/water-3d/Ultra-Water`: `npm install`, потім
`npm run dev`. Стенд — `http://localhost:5199/`; якщо вже працює, другий процес
не запускати. Для `?tiles=story-8-frames-hibrid` Tilecraft читається з
`TILECRAFT_ROOT` або стандартного `D:/work/js-games/ua-dream/tilecraft`.
Інтернет не потрібен. За правилом `AGENTS.md` стенд лишається запущеним після рев'ю.

Телефон: dev-стенд слухає лише `localhost`. Для сценаріїв на телефоні стенд
треба підняти з `--host` (`npm run dev -- --host`) і відкрити
`http://<IP цього ПК в локальній мережі>:5199/` — телефон і ПК в одній мережі.

## U1. Рейка станцій і переліт камери

**Прийнято власником через `handoff:next` 2026-11-23.** Драфт на Netlify
(`edge-of-elements`, 2026-11-23) власник дивився на телефоні; там знайдено квадрат
мілини навколо острова — дефект старший за U1, виправлення — фаза U4. Guard зелений за 0.23 с: OWNER-3 27 → 0 (камеру пише
лише `src/scene/cameraRig.js`, 7 записів), OWNER-4 6, TYPES-1 21. `npm test` 49/49
(31 новий), lint чистий. Проби (AMD Radeon 890M, Chromium ANGLE D3D11, `errors=[]`):
`probe-scene-rail` PASS 97 с; регресія `probe-frame-drag` 34 с (`FD2_SKIP_SOAK=1`),
`probe-scene-ui` 56 с, `probe-frame-lifecycle` 53 с, `probe-tiles` 59 с — PASS.

Автоматично: `node scripts/probe-scene-rail.mjs` записує позу камери **кожен кадр**
9 перельотів (з Lagoon, з-під води, з Aerial, з Tiles; острів ↔ берег ↔ історія):
0 кадрів під рельєфом, 0 кадрів посередині перельоту нижче води + 1 м, найбільший крок
за кадр ≤ 7.5 % шляху, `sky.params` і `ocean.params` незмінні, тривалість ≤ 5 с.
Також: натискання на canvas під час перельоту, захоплення кадру на 80 % перельоту,
неактивна «Історія» без тайлів, клавіші, reduced motion, перекриття рейки й смужки
F2/F3 на телефоні. Очима — те, чого проба не бачить: чи переліт **виглядає** плавним,
що видно з берега, вигляд рейки й намистинки.

### QA-U1-1. Рейка на місці; без історії «Історія» й «Мить» неактивні

**qa:open:** `http://localhost:5199/`
**qa:action:** навести мишу на вузол «Історія» (у браузері з англійською мовою — «Story»).

**qa:expected:** чотири кружки на лінії з підписами `Острів · Берег · Історія · Мить`

над «Історією» — `Історію не завантажено`. Жоден кружок не заповнений (старт — дев-шот Lagoon).

### Свідомо не зроблено в U1

- Станція «Мить» неактивна завжди (підказка `Мить — ще не готова`, коли історія є);
  `app.stations.nextFrame()` / `prevFrame()` повертають `false` — це U2.
- Повноширинна рейка на телефоні, відступи 16 px, місце під кнопку погоди — U3. Зараз
  рейка 304 px по центру й на 412 px екрані влазить.
- Старт сторінки — як і раніше дев-шот Lagoon, не станція: жоден вузол не заповнений,
  поки людина не обере станцію.
- Тривалість перельоту рахується в часі кадрів (`dt` ≤ 0.1 с на кадр): на кадрах-ривках
  > 100 мс переліт на стіні триває довше 5 с (headless-стенд: 5.6–7.9 с; такі самі
  ривки є й на статичній камері — це стенд, не переліт).
- Дев-шоти в Controls → `camera` і далі ставлять сонце (спека §4.4).
- **Відомий дефект, не U1:** на телефонах без `OES_texture_float_linear` навколо острова видно
  квадрат ~1800 м світлої гладкої «мілини» з прямою межею (карта берега читається як нулі).
  Зі станції «Острів» його видно найкраще. Виправлення — фаза U4.

## U0. Технічний UI схований

**Прийнято власником через `handoff:next` 2026-11-22.** Guard зелений за 0.5 с
(OWNER-3 27, OWNER-4 6, TYPES-1 21 — без змін); `npm test` 18/18 (14 нових);
lint чистий. Проби (AMD Radeon 890M, Chromium ANGLE D3D11, `errors=[]`):
`probe-scene-ui` PASS 43.5 с; регресія `probe-tiles` 49 с, `probe-tiles-drift`
189 с, `probe-frame-pose` 51 с, `probe-frame-drag` 45 с (`FD2_SKIP_SOAK=1`) — PASS.
Ручні сценарії на справжньому телефоні й iPhone (QA-U0-7…10) до приймання не
проганялися.

Автоматично: `node scripts/probe-scene-ui.mjs` (потрібен `PLAYWRIGHT_MODULE`, як у
[frame-drag QA](../frame-drag/QA.md)) покриває QA-U0-1…QA-U0-8 у Chromium, включно з
CDP-дотиком трьома пальцями в mobile-профілі. Очима варто подивитися на те, чого
проба не бачить: чи не відкривається браузерний пошук на F3, вигляд смужки, справжні
пальці на телефоні (QA-U0-7…QA-U0-10).

### Свідомо не зроблено в U0

- Рейки камери ще немає: смужка F2/F3 стоїть на `8px` над нижнім краєм; місце над рейкою —
  U3. `viewport-fit=cover` не ввімкнено, тому `safe-area-inset-bottom` на iPhone = 0, і
  сторінка й так не заходить під домашній індикатор.
- Дотик трьома пальцями, перший з яких на кадрі, лишає цей кадр виділеним: FD2 виділяє
  кадр на першому `pointerdown` і зберігає виділення, коли другий палець передає жест
  камері. U0 цю поведінку FD2 не змінює.
- Список `camera` у Controls лишився дев-інструментом і далі ставить сонце (спека §3.1).
