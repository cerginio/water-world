# QA: tile-floaters — плавучі тайли Tilecraft

Як запустити локально:

1. Tilecraft має лежати в `D:/work/js-games/ua-dream/tilecraft` (інакше задайте
   `TILECRAFT_ROOT=<шлях>` перед запуском). Сам Tilecraft сервер не потрібен: його модулі
   й фікстури віддає dev-сервер Ultra Water через `/@fs/`.
2. `cd Ultra-Water && npm install && npm run dev` — сервер на `http://localhost:5199/`
   (порт фіксований, `strictPort`). Інтернет не потрібен.
3. Поле працює лише в `npm run dev`; у `npm run build` список джерел у папці `Tiles`
   неактивний (spec.md §3.2).

Для П5 (порівняння з Tilecraft) потрібен ще статичний сервер Tilecraft:
`cd D:/work/js-games/ua-dream/tilecraft && npm start` → `http://localhost:8080/`.

## T3, поточне виправлення: мерехтіння при waveScale=0

Після коміту `c87e6b6`: стабільна фізична осадка скасовувала y0, включно
зі сходинками шарів/груп Tilecraft. На пласкій воді перекриті верхні грані
ставали компланарними. Для відображення тепер збережено вихідний bottom
відносно найнижчого в полі та додано 0.1 мм за порядком тайла всередині групи.
Зсув `aSurfaceOffset` сталий, передається атрибутом при побудові поля та
не впливає на фізичну осадку й не залежить від waveScale. Дублікати стиків
мають однаковий зсув. Підняті шари можуть виглядати вище за фізичну осадку:
це розділення для відображення, а не розв’язувач зіткнень тайлів.

За прямою вказівкою власника автоматичні тести й build після цього
виправлення не запускалися; наведені нижче результати стосуються попереднього коду.

## T3, попереднє виправлення після рев’ю: «стіни» з полілайнів

Для плавучих стрічок замість незалежних балістичних підскоків використано
критично затухаюче наближення до поверхні. Осадка залежить від density/buoyancy;
нахил наближається до локального схилу хвилі з межею 20°. Внутрішнє затухання
працює й при drag=0. Якщо плавучості недостатньо, стрічка продовжує тонути.
Це спрощена модель стрічки, без повного розв’язувача розтягу й вигину.
На цьому кроці polygon-тайли ще зберігали попередню фізику; наступне
виправлення вище поширило стабілізацію й на них.

LCR sourceOwner може бути віддаленим від згенерованої вершини на кілька метрів.
Для деформації тепер обирається найближчий тайл того самого run; дублікати
стиків, верх і низ мають спільного власника. На справжній фікстурі знайдено
ребро 0.25 мм, яке розтягувалось до 1.74 м навіть після стабілізації фізики.
Після виправлення власників найбільше подовження серед усіх ребер — 0.332 м.

Нова проба: `node scripts/probe-tiles-strip.mjs` (dev-сервер має працювати;
за потреби `PLAYWRIGHT_MODULE` як нижче). Вона використовує програмний GPU
SwiftShader, аналітичні рухомі хвилі й реальну геометрію hybrid, без бенчмарку.
`TILES_PREVIEW=<шлях.png>` зберігає діагностичний рендер самих стрічок.

Перевірено 2026-11-02:

- 24 с хвиль, density 480 → 100 → 750 → 480, buoyancy=1.9,

  max похибка стеження за хвилею з осадкою 0.236 м; нескінченних станів немає.
- Порівняння з попереднім TileSim на тій самій фікстурі: сусідні висоти

- Реальна hybrid-фікстура: 46 861 тайл, 1 105 run-ів, 2 380 452 ребра
  трикутників, maxSeam=0, max подовження ребра 0.332 м після зміни density

## T3. Drift і плавне перемикання

Реалізовано 2026-11-02, передано на рев’ю; фазу ще не закрито.
Стенд: `http://localhost:5199/?tiles=story-8-frames-hibrid&tilesMode=drift`.
Сервер залишається запущеним за правилом `AGENTS.md`.

Polygon-тайли інтегрують дрейф окремо; 1 105 polyline-run-ів мають спільні
горизонтальні позицію й швидкість. Орбіта лишається власною для кожного тайла;
після виправлення рев’ю вертикаль і нахил стрічки слідують поверхні, як описано
вище. Run-прохід працює перед проходом тайлів в обох режимах.
Його MRT містить `uRun=(px,pz,vx,vz)` та історію `(dispX,dispZ,orbit,valid)`.
Для polygon `uState2.xy` — залишкова швидкість пружини в anchored і повна
швидкість у drift; `uState3.z` пам’ятає режим. Перемикання переводить ці швидкості
з урахуванням орбіти, без reset або перебудови. Reset обнуляє обидві пари target-ів
і всю історію. CPU не переписує матриці чи нормалі.

`windage` задає частку швидкості вітру OceanSim; `driftRadius` (50–1000 м,
типово 400 м) — відстань від центра поля до початку м’якої стінки. Це сила,
тому невеликий вихід за радіус допустимий. Для run обмежується центроїд;
кінці стрічки та власна орбіта можуть лежати далі. `tiles*` у URL зберігають
контроли після завершення введення; `frame` із URL зіставляється з id моделі.
Для локального файла URL записує `tiles=none`: файл треба вибрати повторно.
Сторонні параметри й hash зберігаються.

Eval на AMD 890M / headless Chromium, 1400×1000:

- **Guard:** `npm run build` PASS. Бенчмарк `tiles=none` ±0.05 мс від README
  на RTX 3060 лишається неперевіреним обмеженням T0; структурна перевірка none PASS.
- **Probe, базова:** `node scripts/probe-tiles.mjs` PASS, 46 861 скінченний стан,
  218 196 пар стиків, maxSeam=0, помилок 0; CPU renderFrame +0.1153 мс
  (бюджет +0.5 мс), GPU обох проходів ≈0.407 мс в останній вибірці цієї проби.
- **Probe, T3:** `node scripts/probe-tiles-drift.mjs` PASS, 120.2284 с
  інтегрованого часу / 7 214 кадрів; polygonMax=31.6874 м, runMax=37.9170 м,
  nonfinite=0, 218 196 пар стиків із maxSeam=0. Відхилення тайла від спільного
  зсуву run + власної орбіти ≤0.000002 м.
- Після переходу в anchored: за 12.0163 с максимальний залишок пружини
  0.00000655 м; власна орбіта продовжує працювати. Перемикання до наступного
  кроку GPU не змінює позицій; перевірено обидва напрямки, включно зі швидкістю
  орбіти 2.34375 м/с у контрольній фікстурі.
- Незалежна пласка фікстура при yaw=57°: вітер 10 м/с, windage=0.05,
  за 10 с зсув 4.68951 м проти аналітичних 4.68750 м (похибка 0.00201 м);
  спільний зсув run точний. Windage=0 → зсув 0. При тестовому радіусі 3 м
  і вітрі 25 м/с рівновага центрів 3.99999 м; reset усіх target-ів дає 0.
- URL round-trip усіх параметрів PASS: frame=2, 3 978 тайлів, зокрема
  density=730, windage=0.073, driftRadius=120. Некоректні mode/frame/числа
  нормалізуються; сторонній `keep=ok` і hash лишаються. Помилок 0.
- GPU обох проходів у довгій пробі ≈0.270–0.362 мс, CPU submit ≈0.068–0.091 мс.
  Це вимірювання на AMD 890M, не підтвердження бюджетів RTX 3060 з T4.

Для команд нижче за потреби задайте `PLAYWRIGHT_MODULE`, як у секції T1.
Скриншоти: `%TEMP%/tile-t3-drift-2min.png` і `%TEMP%/tile-t3-returned.png`.
