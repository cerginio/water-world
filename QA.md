# QA: tile-floaters — плавучі тайли Tilecraft

Як запустити локально:

1. Tilecraft має лежати в `D:/work/js-games/ua-dream/tilecraft` (інакше задайте
   `TILECRAFT_ROOT=<шлях>` перед запуском). Сам Tilecraft сервер не потрібен: його модулі
   й фікстури віддає dev-сервер Ultra Water через `/@fs/`.
2. `cd Ultra-Water && npm install && npm run dev` — сервер на `http://localhost:5199/`
   (порт фіксований, `strictPort`). Інтернет не потрібен.
3. Поле працює лише в `npm run dev`; у `npm run build` список джерел у папці `Tiles`
   неактивний (spec.md §3.2).

Для П5 (порівняння з Tilecraft) потрібен ще статичний сервер Tilecraft:
`cd D:/work/js-games/ua-dream/tilecraft && npm start` → `http://localhost:8080/`.

## T2. Динаміка вертикалі й anchored

Закрито 2026-11-02: власник прийняв фазу командою `handoff:next`. Перевіряти на
`http://localhost:5199/?tiles=story-8-frames-polygon`.
Стенд залишається запущеним за правилом `AGENTS.md`.

Тепер висоту й нахил визначають сили, інерція та опір, а не пряме копіювання
води. `density`, `buoyancy`, `drag`, `angularDrag`, `orbit`, `anchorPeriod` і `reset`
доступні в папці `Tiles`. Режим поки завжди anchored; `mode`, `windage`,
run-прохід і збереження фізичних параметрів у URL — T3.

Два MRT-target-и по 4 RGBA32F attachments; рівно 4 вибірки `waterAt` на тайл
за кадр, до 8 підкроків. Для стабільності фізичний dt обмежено `1/30 с`:
при частоті нижче 30 fps фізика відстає від годинника хвиль. Похідна зміщення
води використовує фактичний dt кадру. Поля `uState3.y/w` зберігають попередній
`orbit` і валідність історії. Reset обнуляє обидва target-и; перша швидкість
води після load/reset/відновлення — 0. Формула осадки використовує центр
тайла (як у Floaters); для нульових радіуса/товщини мінімум фізики — 1 мм.

Eval T2, 2026-11-02, AMD 890M / headless Chromium, 1400×1000:

- Guard: `npm run build` — PASS. Точність бенчмарку README ±0.05 мс на
  RTX 3060 не перевірена; обмеження з T0 лишається.
- Коротка WebGL-проба: PASS, 46 861 тайл, помилок 0; рух обох конвеєрів,
  218 196 пар стиків з `maxSeam=0`, матриці/нормалі CPU не переписуються.
  При `fieldYaw=57` похибка незалежного WaterQuery для збереженого зміщення
  центра `1.49e-8 м` (допуск `0.002 м`). Висота тайла тепер має фізичне
  запізнення щодо води. Останній приріст CPU всього кадру `+0.2375 мс`
  (бюджет +0.5 мс), CPU submit ≈0.230 мс, GPU `tiles` ≈0.477 мс.
  У попередньому прогоні, що перетнувся зі збіркою, приріст CPU був
  `+0.9347 мс`; без паралельної збірки повтор дав +0.2375 мс.
- На пласкій воді осадка при density 900/200 відповідає
  `y = h·(0.5 − density/(1025·buoyancy))`; перевірені тонкі та нульового радіуса
  тайли, довгий кадр `dt=0.5 с`, reset, NaN/Infinity → rest → скінченний стан.
  Початковий варіант із sampler без `highp` та `isnan` пропускав пошкоджені
  текстури на ANGLE/D3D; виправлено високою точністю sampler-ів і перевіркою
  бітів експоненти. Початковий зсув 5 м після 3 періодів пружини:
  0.5 с → `2.89e-6 м`, 4 с → `8.54e-7 м`, 20 с → `6.86e-7 м`.
  Кнопка reset перевірена тричі; `orbit=0` дає зсув x/z рівно 0 м.
- Тривала WebGL-проба: PASS, 303.114 с інтегрованого часу, 13 890 кадрів,
  46 861 polygon-тайл; `nonfinite=0`, помилок 0. Максимальний зсув 2.8892 м,
  максимальна орбіта 2.8892 м, залишок пружини 0 м; нахил ≤60°, |vy|≤10 м/с.
  Остання вибірка GPU `tiles` ≈0.503 мс, CPU submit ≈0.190 мс; це не RTX 3060.

Коротка проба: `node scripts/probe-tiles.mjs`.
Тривала: `node scripts/probe-tiles-anchored.mjs` — 300 с **інтегрованого** часу
на polygon-полі після зміни density 900 → 200; при повільних кадрах це займає
більше 5 хв реального часу. Для обох команд задайте `PLAYWRIGHT_MODULE`, як у
блоці T1 нижче, якщо Playwright установлений глобально. Скриншоти лежать у
`%TEMP%/tile-t2-*.png`; докази не додаються до репозиторію.

## T1. Матеріал GPU-стану і кінематика

Закрито 2026-11-02: власник прийняв фазу командою `handoff:next`.

Історичний стан T1 (у T2 замінено фізикою): кінематика без інерції,
`y0 + waterAt(...).y`, нахил за центральними різницями
вздовж осей поля. Один MRT-прохід на тайли; вершини лише читають готовий стан.
`Tiles CPU submit` у Performance — CPU-час подання GPU-проходу, не час усього кадру.
Рядок GPU `tiles` — час цього проходу (на vsync частота GPU може бути знижена).

Eval T1, 2026-11-02, AMD 890M / headless Chromium, 1400×1000:
`npm run build` — PASS; WebGL-проба — PASS, помилок 0. 46 861 скінченний стан,

WaterQuery максимум на `1.2e-7 м`, нормаль — на `0.00016`; GPU `tiles` ≈ `0.33 мс`,
CPU submit ≈ `0.12 мс`. У двох завершальних прогонах приріст CPU усього кадру
відносно статичного поля: `+0.1625 мс` і `−0.0465 мс` (шум; обидва ≤ `0.5 мс`).
Точність guard-бенчмарку README на RTX 3060 лишається неперевіреною.

Автоматична перевірка: при запущеному dev-сервері виконати
`node scripts/probe-tiles.mjs` з установленим Playwright. Якщо він установлений
поза репозиторієм, у PowerShell цієї машини:

```powershell

node scripts/probe-tiles.mjs
```

Проба перевіряє реальні Float32 MRT-текстури, рух обох конвеєрів, стики,
незмінність версій instanceMatrix/normal, світові координати й нормалі через
незалежний WaterQuery при `fieldYaw=57`, перебудови кадру/масштабу та `tiles=none`.
CPU-час усього renderFrame порівнюється з матеріалами статичного T0 на тому самому
полі: 2 черговані раунди на режим, по 90 кадрів після 30 кадрів прогріву,

Скриншот — `%TEMP%/tile-t1-field.png`; файли доказів не пишуться в репозиторій.
Очима перевіряються форма стрічок, мерехтіння та освітлення під час руху.
