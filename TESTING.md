# Як перевіряти Ultra-Water

Правила про перевірки, не про систему. Межі системи — [INVARIANTS.md](INVARIANTS.md),
рішення без механізму — [DECISIONS.md](DECISIONS.md).

## Рівні прогону

Виміряно 2026-11-22, desktop, Node 24.19.

| рівень | команда | що | час | блокує |
|---|---|---|---|---|
| guard | `npm run guard` | 9 статичних правил + тайпчек окремим процесом (TYPES-1) | 0.3 с теплий, ~1 с холодний tsc | **так**, перед кожним комітом фази |
| fast | `npm test` | vitest: 4 офлайн-скрипти `scripts/test-*.mjs` (T4, T5, FD1, terrain contact) | 3–4 с | ні |
| lint | `npm run lint` | oxlint, `correctness` = error, **0 помилок / 0 попереджень** (нове попередження — сигнал, не шум) | 0.3–0.6 с | ні, у guard не входить |
| probe | `node scripts/probe-*.mjs` | Playwright + стенд `localhost:5199` | 44 с (`terrain-contact`) … 103 с (`frame-lifecycle`) | ні |
| full | `npm run test:build`, `test:portability` | збірка в переміщених теках | хвилини | ні |

Блокувати має право лише guard. Порядок у фазі: **guard → focused → probe**.
Повний прогін — не доказ і не місце, з якого починати; звіт фази дає числа
**окремо по рівнях**.

`guard --report` — лише звіт (код 0); `guard --no-types` — без тайпчеку;
`guard --baseline` **друкує** нові baseline OWNER-3/4, файл не пише — зміна
боргу має бути видна в diff (P12).

## Правила для перевірок

**Правило доводиться мутацією, не зеленим прогоном.** Нове правило guard
спершу проходить на чистому коді, потім падає на мутації реального джерела з
іменем файлу; мутацію прибрати. Таблиця мутації — у секції інваріанту.
Походження: bootstrap 2026-11-22, 11 мутацій на 10 правил.

**Перевірка на порожньому наборі — не перевірка (P10).** Кожне правило guard
тримає розмір набору: `engine/` ≥ 4 файли, рівно 2 файли неба, ≥ 1 import у
завантажувачі, фрагмент води ≥ 10 семплерів.

**Порожній вивід інструмента — збій, не успіх (P4).** Інструменти
викликаються прямо (`node node_modules/typescript/lib/tsc.js`), не через
`npx`: на Windows `npx.cmd` через `execFileSync` віддає порожній stdout
(інцидент `three`, Д5).

**Офлайн-скрипти лишаються самостійними.** `scripts/test-*.mjs` — на
`node:assert`, на них посилаються HANDOFF і QA; vitest
([tests/offline-scripts.test.js](tests/offline-scripts.test.js)) лише імпортує
кожен як один тест. Новий юніт — `tests/**/*.test.js`; новий офлайн-скрипт —
додати і в цей список.

**Vitest не в guard.** Холодний старт vitest ~1.8 с з'їдає бюджет guard
(< 2 с), тому BUDGET-1 живе в guard як статичне правило, а не як юніт.
